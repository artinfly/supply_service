# supply_service — отчёты отдела снабжения (МТО УВЗ)

Веб-сервис на Django + PostgreSQL для отдела снабжения: загружает Excel-выгрузки
(договоры, заявки на платёж ФЗД и SAP), показывает сводки и реестры, формирует отчёты в Excel.

## Возможности

- **Сводки** — договорная работа, заявки на платёж (ФЗД и SAP): карточки, таблица по ЦФО, графики.
- **Реестры** — все договоры и все заявки с фильтрами по контрагенту, ИГК, ЦФО, году и статусу.
- **КДР** — заключение договоров по ИГК за год.
- **ИГК по годам** — заключённые, незаключённые и расторгнутые договоры с детализацией.
- **История изменений** — смена статуса, плана и факта между загрузками.
- **Дубликаты** — повторяющиеся позиции договоров.
- **Отчёты в Excel** — авансы, КДР, договоры по контрагенту, история, дубликаты, появившиеся договоры.
- **Краткая справка** — справки по каждому ИГК из файла «Свод отчёт по ИГК».
- **Анализ ГОЗ** — отчёт по архиву форм ЕИС ГОЗ и справочник ГК со ставками НДС.
- **Права** — доступ к каждому разделу выдаётся пользователю в админке.

## Быстрый старт

Нужны Python 3.14 и PostgreSQL 16+ с расширением `pgcrypto` (его включает миграция `0014_pgcrypto`;
пользователю БД нужны права на `CREATE EXTENSION`, либо включите расширение заранее).

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows; в Linux: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env            # и заполните значения
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Сайт открывается по адресу http://127.0.0.1:8000/reports/, админка — /admin/.

## Права доступа

Пользователю в админке отмечаются разделы («Доступ к разделам»). Каждый адрес сайта привязан к разделу
в `core/middleware.py`. Адрес, которого нет в этой таблице, доступен только суперпользователю —
при добавлении новой страницы впишите её имя туда.

Справочник ГК: загрузить из файла может только суперпользователь, добавлять, править и удалять
записи вручную — все, у кого есть доступ к «Анализу ГОЗ».

## Загрузка данных

Страница «Загрузка данных» или консоль:

```bash
python manage.py load_contracts путь\к\договорам.xlsx
python manage.py load_znp путь\к\знп_фзд.xlsx
python manage.py load_znp_sap путь\к\знп_sap.xlsx
```

Порядок колонок не важен (кроме SAP — там колонки по номерам, см. `ZNP_SAP_COLUMNS`
в `services/importing/excel_import.py`). При повторной загрузке договоров изменения статуса,
плана и факта записываются в историю, а справочник ИГК приводится к ИГК из файла.
Если в файле нет ни одной подходящей строки (например, выбран не тот тип файла),
загрузка отменяется и прежние данные остаются.

## Добавление нового года (например, 2028)

1. `core/services/queries.py`: `YEARS = [2025, 2026, 2027, 2028]`.
2. `core/models.py`, модель `IgkStatData`: поле `y28 = models.BooleanField(null=True, ...)`.
3. `core/services/importing/normalize.py`: добавить `y28` в `Position`, в `_read_contract_staging`
   и в `INSERT INTO igk_stat_data` (`_write_positions`).
4. Поиском по проекту найти `y27` и добавить `y28` рядом (SQL в `queries.py`, шаблоны).
5. `python manage.py makemigrations` и `python manage.py migrate`, затем перезагрузить файл договоров.

## Тесты и форматирование

```bash
python manage.py test
```

Django создаёт временную тестовую базу, поэтому пользователю PostgreSQL нужно право
`CREATEDB`. Код отформатирован black и isort (настройки в `pyproject.toml`).

## Известные ограничения

- Заявки ФЗД привязываются к позициям договоров по CRC32 (`services/importing/linking.py`);
  при редком совпадении хешей заявка может привязаться не к той позиции.
- Краткая справка «Длинноцикловая» строится только по договорам с «Да» в колонке
  «Длинноцикловые» (столбец G); «Обычная» — по всем договорам.
- КДР на экране считает только позиции с заказом, выгрузка КДР в Excel — все позиции (так задумано).
