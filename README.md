# supply_service — отчёты отдела снабжения (МТО УВЗ)

Веб-сервис на Django + PostgreSQL. Загружает Excel-выгрузки (договоры, заявки на платёж ФЗД и SAP),
показывает сводки и реестры, формирует отчёты в Excel: КДР, авансы, историю изменений,
«Анализ ГОЗ» по архиву ЕИС и краткую справку по ИГК.

## Быстрый старт

Нужны Python 3.13 и PostgreSQL 16+ с расширением `pgcrypto` (его включает миграция `0014_pgcrypto`;
пользователю БД нужны права на `CREATE EXTENSION`, либо включите расширение заранее).

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows; в Linux: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env            # и заполните значения
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Сайт открывается по адресу http://127.0.0.1:8000/reports/, админка — /admin/.

## Права доступа

Пользователю в админке отмечаются разделы («Доступ к разделам»). Каждый адрес сайта привязан к разделу
в `core/middleware.py`. Адрес, которого нет в этой таблице, доступен только суперпользователю —
при добавлении новой страницы впишите её имя туда.

Справочник ГК: загрузить из файла может только суперпользователь, добавлять, править и удалять
записи вручную — все, у кого есть доступ к «Анализу ГОЗ».

## Загрузка данных

Страница «Загрузка данных» или консоль:

```bash
python manage.py load_contracts путь\к\договорам.xlsx
python manage.py load_znp путь\к\знп_фзд.xlsx
python manage.py load_znp_sap путь\к\знп_sap.xlsx
```

Порядок колонок не важен (кроме SAP — там колонки по номерам, см. `ZNP_SAP_COLUMNS`
в `services/importing/excel_import.py`). При повторной загрузке договоров изменения статуса,
плана и факта записываются в историю.

## Анализ ГОЗ: формат ключа ГК

ИГК — последние 4 цифры длинного номера. Число после пробела — спецификация.
Номер договора 137 в ключ не пишется, если стоит сразу после «сб» (`…_334сб_137`)
или после ИГК в договоре (`…1493/137 от …`). Но спецификация тоже бывает номер 137:
файл без «сб» `…0262_137` → `0262 137`, справочник `…0262/255сб/137 от …, спец…./137` → `0262/255сб 137`.

| Имя файла в архиве (после №…) | Договор/Дата в справочнике | Ключ |
|---|---|---|
| `…1493` | `…1493/137 от …` | `1493` |
| `…6766_12` | `…6766/12 от …` | `6766 12` |
| `…0087_334сб_137` | `…0087/334сб/137 от …` | `0087/334сб` |
| `…0276_481сб_137_138` | `…0276/481сб/137 от …, спец…/138` | `0276/481сб 138` |
| `…0998_439сб_19` | `…0998/439сб/19 от …` | `0998/439сб 19` |
| `…4238_3_3_6_30-2014-ДГОЗ` | — | `4238_3_3_6_30-2014-ДГОЗ` |

Файлы с нечётной «Стр. N» в архиве пропускаются. Логика — `core/services/goz/gk_key.py`.

Поиск в справочнике (`find_gk` в `gk_directory.py`): сначала точное совпадение ключа,
затем для «ИГК спец» без сб — единственная запись «ИГК/NNNсб спец» (файл `…9741_136`
находит `9741/255сб 136`). Если таких записей несколько, ГК считается новым.

Разные ИГК с одинаковыми последними 4 цифрами (например, `…2224…209741` и `…2525…209741`)
дают один ключ. При загрузке архива об этом выводится предупреждение.

## Добавление нового года (например, 2028)

1. `core/services/queries.py`: `YEARS = [2025, 2026, 2027, 2028]`.
2. `core/models.py`, модель `IgkStatData`: поле `y28 = models.BooleanField(null=True, ...)`.
3. `core/services/importing/normalize.py`: в `normalize_contracts` добавить `y28` в разбор
   `year_flags`, в кортеж строки и в `INSERT INTO igk_stat_data`.
4. Поиском по проекту найти `y27` и добавить `y28` рядом (SQL в `queries.py`, шаблоны).
5. `python manage.py makemigrations` и `python manage.py migrate`, затем перезагрузить файл договоров.

## Известные ограничения

- Заявки ФЗД привязываются к позициям договоров по CRC32 (`services/importing/linking.py`);
  при редком совпадении хешей заявка может привязаться не к той позиции.
- Краткая справка «Длинноцикловая» строится только по договорам с «Да» в колонке
  «Длинноцикловые» (столбец G); «Обычная» — по всем договорам.
- КДР на экране считает только позиции с заказом, выгрузка КДР в Excel — все позиции (так задумано).

```bash
pg_restore -h localhost -U root -d supply_service_test --clean backup.dump
```
